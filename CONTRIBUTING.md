# Contributing to Lipp Board

Thanks for helping improve Lipp Board.

## Before opening a PR

- keep the change focused
- run `npm run build`
- run `npm run lint`
- run `npm test`
- verify the layout on a mobile viewport when the change touches UI

## Repo rules

- prefer the smallest working diff
- reuse existing components and helpers before adding new ones
- keep the project PWA-first
- avoid adding dependencies unless they clearly reduce complexity
- keep personal defaults out of the public base when possible

## Good PRs

A good PR is one that:

- explains what changed
- includes screenshots for UI changes
- keeps the app installable and stable as a PWA
- does not leave the repo dirty
